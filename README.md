# T7. Интерпретируемость детектора подозрительных транзакций (Elliptic Bitcoin)

Проект по курсу XAI (НИУ ВШЭ): реализация дизайн-документа ДЗ-3.
Модель — Skip-GCN на графе транзакций Elliptic. Пользователи объяснений — AML-аналитик и регулятор.

- **Результаты и ответы пользователям:** [REPORT.md](REPORT.md)
- **Дизайн-документ:** [v2 с разделом «что изменилось и почему»](docs/design_doc_v2.md), [v1 (сдан как ДЗ-3)](docs/design_doc_v1.md)

**Главный вывод.** Объяснение по потокам (IG) верно описывает модель, но обоснованием блокировки служить не может: структурное объяснение чаще есть у ложных алертов («виновность по связи»). Модель годится для сортировки очереди аналитика.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Нужен только CPU. При первом запуске PyG сам скачивает Elliptic в `data/elliptic/` (около 700 МБ).
Если скачивание не проходит, возьмите три CSV с Kaggle (`ellipticco/elliptic-data-set`) и положите их в `data/elliptic/raw/`.

## Запуск

Всё сразу, из чистого клона (~50 мин на CPU):

```bash
bash scripts/run_all.sh
```

По шагам:

| Шаг | Команда | Что получится | Время (CPU) |
|---|---|---|---|
| 1 | `python scripts/step1_models.py` | 5 моделей Skip-GCN, RF, пороги τ, метрика M-10 | ~17 мин (MacBook Air M-серии) |
| 2 | `python scripts/step2_explain.py` | М1 (IG по рёбрам) и М2 (IG: локальные / агрегаты / рёбра) для всех тестовых алертов seed 0, M-7 | ~13 мин |
| 3 | `python scripts/step3_cf_knn.py` | разбивка шага 2 по группам; М4 и M-9; М3 и M-8 на оценочной выборке | ~4 мин |
| 4 | `python scripts/step4_faithfulness.py` | метрики верности M-1…M-6 | ~3 мин |
| 5 | `python scripts/step5_protocol.py` | протокол М5 (два варианта проверяемости), сигналы надёжности, карточки алертов | ~6 мин |
| 6 | `python scripts/step6_fragility.py` | хрупкость: камуфляж (Б.2), подбор сида банком (Б.3) | ~6 мин |
| — | `python scripts/make_figures.py` | графики для отчёта и слайдов в `artifacts/figures/` | секунды |

Быстрая проверка без настоящих данных (около минуты):

```bash
python tests/make_fake_elliptic.py data/fake_elliptic
python scripts/step1_models.py --root data/fake_elliptic --out artifacts_test --epochs 30 --seeds 0 1
```

## Уточнения и отклонения от документа v1

Изменения протокола М5 и новые методы v2 описаны в [docs/design_doc_v2.md](docs/design_doc_v2.md). Ниже — технические отклонения реализации.


1. **Вес ребра.** Один направленный поток $e$ получает один вес $w_e$, общий для обоих направлений после симметризации. Так IG в М1 даёт один вклад на один реальный поток.
2. **Порог τ.** Берётся минимальный τ, при котором precision illicit на шагах 30–34 не ниже 0,8. Если такого порога нет, берётся τ с максимальным F1, а в `thresholds.json` ставится `precision_target_met: false`.
3. **Шаг времени и txId.** PyG не хранит их в `Data`, поэтому они читаются из сырого CSV и кешируются в `processed/meta.npz`.
4. **macOS.** В скрипте выставлено `KMP_DUPLICATE_LIB_OK=TRUE`: torch и scikit-learn загружают разные копии OpenMP.
5. **Окрестность в М1.** Переменные IG — рёбра 2-хоп окрестности $E_v$, как в документе. Но считаем на индуцированном 3-хоп подграфе, а рёбра к 3-му кольцу держим с весом 1: от них зависят степени узлов 2-го кольца, то есть нормировка GCN. На голом 2-хоп подграфе $z(v)$ не совпал бы со значением на всём графе. Совпадение проверяется в `summary.json`.
6. **Алерты.** Транзакции с $p \ge \tau$ на шагах 35–49, включая неразмеченные: для seed 0 их 7 983, из них размеченных около 1 240. М1 и М2 считаются для всех. М3, М4 и метрики — на оценочной выборке: все размеченные алерты плюс 500 случайных неразмеченных (seed 0).
7. **Малые окрестности.** Медиана $|E_v| = 5$, поэтому у половины алертов «top-5 рёбер» — это все рёбра, и условие достаточности М5 и Fidelity− выполняются тривиально. Пороги не меняем: они зафиксированы до расчёта. Но эти метрики дополнительно показываем на алертах с $|E_v| > 10$.
8. **Порядок рёбер в M-1…M-3.** Рёбра ранжируются по $\mathrm{IG}_e$ со знаком, а не по $|\mathrm{IG}_e|$, как в карточке аналитика. Иначе удаление «важных» рёбер смешивало бы рёбра, повышающие и понижающие $z$.
9. **GNNExplainer.** Используется собственная реализация цели Ying et al. (2019) с коэффициентами по умолчанию из PyG, по тем же весам рёбер $E_v$, что и IG. Стандартный `torch_geometric.explain` маскирует сообщения, а в нашей модели граф симметризуется внутри `forward`, поэтому размер его маски не совпал бы. Считается на 300 алертах вместе с M-5 и M-6.
10. **Проверяемость (C5) в М5.** Считаются два варианта. Первый — как в документе: ребро ведёт к размеченной illicit-транзакции или к транзакции со скором ≥ τ. Второй, строгий, — только к размеченной illicit. Вариант «по скору» использует оценку самой модели, то есть объяснение подтверждает модель её же выходом, поэтому добавлен строгий вариант.
